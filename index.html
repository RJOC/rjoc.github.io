Email & Phishing

Phishing / suspicious email reported

High
Fires on
User-reported email, or gateway rule (e.g. credential-harvesting link pattern)
Check first
Raw headers — SPF/DKIM/DMARC in Authentication-Results, From vs Return-Path, sender domain age
Scope it
Search mail logs for same sender/subject/URL hash across the whole org, not just the reporter
Contain
Block sender/URL/hash at gateway, purge from other inboxes, force reset if creds were entered

Interviewer wants to hear: did you check impact beyond the one reporting user, and did you verify whether credentials were actually submitted?

Malicious attachment / macro-enabled document

High
Fires on
Sandbox detonation flags macro behavior, or AV/AMSI catches obfuscated VBA
Check first
Detonate in sandbox, not locally; check hash against VirusTotal/threat intel

Endpoint & Malware

Suspicious / encoded PowerShell execution

High
Fires on
AMSI-driven EDR alert, or command-line flags in process creation (Event 4688 / Sysmon ID 1)
Check first
Command line for -enc, -ExecutionPolicy Bypass, -WindowStyle Hidden; parent process; any outbound connection right after launch
Key concept
AMSI inspects content in memory after deobfuscation — you don't need to manually decode it yourself
AMSIFalcon Script ControlEvent ID 4104IOA behavior graph
Interviewer wants to hear: you know how detection works without reading the script — AMSI/EDR content inspection plus behavioral signals (parent process, network activity), not just "I'd look at the code."

Generic malware / AV-EDR detection

High
Fires on
Signature match, heuristic, or ML verdict from EDR agent
Check first
Was it blocked/quarantined or just detected-and-allowed; file hash and prevalence across the fleet
Scope it
Same hash/IOC on other endpoints; how it landed (download, USB, email, lateral movement)
Hash lookupFleet-wide searchIsolation
Interviewer wants to hear: containment (isolate the host) before full root-cause, and confirmation the block actually worked.

Ransomware indicators

High — P1
Fires on
Mass file rename/encryption pattern, shadow copy deletion (vssadmin), backup deletion attempts
Check first
Isolate the host immediately — this is a "contain now, investigate after" scenario
Scope it
Shared drives/network shares touched from that host; other machines showing the same pattern
vssadmin delete shadowsMass file modify rateNetwork isolation
Interviewer wants to hear: speed and containment-first instinct — you isolate before you fully diagnose, because time directly equals blast radius here.

Identity & Access

Failed login spike / brute force

Medium–High
Fires on
Threshold of failed auth attempts against one account or across many accounts from one source
Check first
Single account (targeted) vs spray across many accounts (password spray); source IP reputation
Escalate if
A failure streak is followed by a success — that's the real signal, not the failures alone
Sign-in logsConditional AccessIP reputation
Interviewer wants to hear: you check whether it eventually succeeded — failed logins alone are noisy, a success after failures is the actual incident.

Impossible travel / anomalous sign-in location

Medium–High
Fires on
Same account authenticating from two geographically distant locations in an impossible timeframe
Check first
VPN/corporate proxy exit points (common false positive); device compliance state; MFA method used
Contain
Revoke session tokens, force re-auth with MFA, reset credentials if compromise confirmed
Sign-in logsToken revocationDevice compliance
Interviewer wants to hear: you rule out the common false positive (corporate VPN) before treating it as a real compromise.

MFA fatigue / push bombing

Medium–High
Fires on
Repeated MFA push notifications to one user in a short window
Check first
Did the user ever accept one of the pushes; source IP of the requests
Contain
Reset credentials immediately if a push was accepted, treat as account compromise, not just noise
Number matching MFASign-in logs
Interviewer wants to hear: you know this is an attacker who already has valid credentials and is trying to bypass the second factor — not a benign glitch.

New privileged account / unexpected admin role grant

High
Fires on
Account added to a privileged group (Domain Admins, Global Admin) outside change management
Check first
Who made the change, was it via an approved ticket, does the account's normal behavior match admin activity
Audit logsChange ticket correlation
Interviewer wants to hear: you treat unexplained privilege escalation as a potential compromise indicator, not just an HR/IT process question.

C2 beaconing / suspicious outbound traffic

High
Fires on
Regular-interval outbound connections to a rare or newly-registered domain/IP
Check first
Destination reputation and domain age; beacon interval regularity; process that initiated the connection
Contain
Block at firewall/proxy (NGFW URL category), isolate host, hunt for the same IOC elsewhere
NGFW URL filteringnewly-registered-domainDNS logs
Interviewer wants to hear: you know beacon regularity (not just destination reputation) is itself a signal, and where to enforce the block (firewall/proxy vs endpoint).

Was it blocked or just logged; source IP volume/pattern (scanner vs targeted); which endpoint was hit

Compliance & Risk

Risk fundamentals: likelihood × impact

Core idea
Risk = Likelihood × Impact. Used to decide what actually gets fixed first — not the same thing as raw technical severity.
Know cold
Inherent risk (before controls) vs residual risk (what's left after controls); risk appetite (how much you're willing to accept) vs risk tolerance (acceptable variance around that); four treatment options — accept, mitigate, transfer, avoid
Residual riskRisk registerAccept / Mitigate / Transfer / Avoid
Sample question: "How would you prioritize two vulnerabilities with the same CVSS score?" — good answer weighs business context: is it internet-facing, how critical is the asset, are there compensating controls — not just the raw score.

Policy vs standard vs procedure vs guideline

Core idea
A governance hierarchy, top-down: Policy (high-level mandate — "passwords must meet complexity requirements") → Standard (specific measurable requirement — "minimum 14 characters, MFA required") → Procedure (step-by-step how-to for IT to implement it) → Guideline (recommended, not mandatory).
PolicyStandardProcedureGuideline
Sample question: "What's the difference between a policy and a standard?" — answer with a concrete example pair, don't just define the terms abstractly.

Common compliance frameworks

Core idea
Different frameworks solve different problems — know what each is actually for, not just the acronym.
Know cold
NIST CSF — voluntary risk framework, 5 functions: Identify, Protect, Detect, Respond, Recover. ISO 27001 — certifiable ISMS standard with Annex A controls. SOC 2 — trust service criteria, common ask when vetting SaaS vendors. PCI-DSS — mandatory if you handle cardholder data. GDPR — EU data privacy regulation, not a security control framework.
NIST CSFISO 27001SOC 2PCI-DSSGDPR
Sample question: "Which framework would you check before onboarding a new vendor?" — answer depends on what the vendor handles: request their SOC 2 report for a SaaS tool, PCI-DSS attestation if they touch card data. Show judgment, not memorization.

Control types

Core idea
Controls are categorized two ways: by function (preventive, detective, corrective) and by nature (administrative, technical, physical).
Examples
Preventive = firewall rule blocking traffic. Detective = SIEM alert firing. Corrective = incident response runbook restoring a service. Administrative = security awareness training. Technical = MFA. Physical = badge access to a datacenter.
Sample question: "Give me an example of a detective control vs a preventive one." — have one crisp example of each ready, don't fumble for it live.

Audit findings & compensating controls

Core idea
When an audit finds a gap you can't immediately fix (e.g., a legacy system that can't support MFA), a compensating control offsets the risk in the meantime — network segmentation, enhanced logging, restricted access — until the real fix ships.
Sample question: "How would you handle an audit finding you can't fix right away?" — good answer: document a remediation plan with a timeline, propose a compensating control, and get formal risk acceptance from the right owner if the fix will be delayed a while. Shows you won't just let a finding sit silently.

Network Fundamentals

OSI model — mapped to security relevance

Core idea
Interviewers usually want you to map attacks and tools to layers, not recite all seven from memory.
Know cold
L2 (Data Link) — ARP spoofing, MAC flooding. L3 (Network) — IP spoofing, ICMP abuse. L4 (Transport) — TCP/UDP, port scanning, SYN floods. L7 (Application) — HTTP-based attacks, SQLi, XSS, phishing.
Sample question: "Where does DNS spoofing happen in the OSI model?" — DNS itself is L7, but cache-poisoning attacks exploit response-spoofing that touches L3/L4 too. The point is showing you can reason about it, not recite the stack top to bottom.

TCP three-way handshake & scanning

Core idea
SYN → SYN-ACK → ACK establishes a TCP connection. Understanding this explains why a SYN ("half-open") scan is stealthier than a full connect scan, and why a SYN flood works as a DoS technique — the target holds open half-completed connections until resources exhaust.
Sample question: "How would you detect port scanning on your network?" — a high volume of SYN packets without completed handshakes from one source, sequential port attempts in firewall logs, or an IDS/IPS signature match.

Firewall types & segmentation

Core idea
Stateless (evaluates each packet in isolation) vs stateful (tracks connection state) vs NGFW (adds application-layer awareness, URL filtering, intrusion prevention). Segmentation — VLANs, subnets, zero trust boundaries — limits how far an attacker can move after landing on one host.
Sample question: "Why would you segment a network?" — to contain blast radius: a compromised workstation in one VLAN shouldn't be able to reach finance servers in another without crossing an enforced, logged boundary.

DNS fundamentals & abuse

Core idea
DNS resolves names to IPs — and gets abused two main ways: DNS tunneling (encoding stolen data into subdomain queries to exfiltrate through a protocol that's rarely blocked outbound) and cache poisoning/typosquatting (redirecting users to malicious infrastructure).
Sample question: "How could DNS be used for data exfiltration?" — DNS tunneling: encode data into queries sent to an attacker-controlled authoritative nameserver, since outbound port 53 is almost never blocked the way other ports are.

Attack & Defense

Cyber Kill Chain

Core idea
Lockheed Martin's 7-stage model of an attack: Reconnaissance → Weaponization → Delivery → Exploitation → Installation → Command & Control → Actions on Objectives.
Sample question: "Where would you want to stop an attacker?" — as early as possible (recon/delivery) in principle, since damage compounds the further right you go — but be honest that most real-world detections land in the middle (exploitation/installation/C2), which is exactly why layered defense matters.

MITRE ATT&CK

Core idea
A knowledge base of real-world adversary tactics and techniques (e.g., T1566 Phishing, T1059.001 PowerShell), used to benchmark what your detections actually cover — not a linear attack story like the kill chain.
Sample question: "How is ATT&CK different from the kill chain?" — kill chain is a high-level linear lifecycle; ATT&CK is a detailed, non-linear matrix of specific techniques used to map detection coverage and find gaps.

Defense in depth

Core idea
Layered controls so no single failure equals full compromise: perimeter (firewall) → network (segmentation) → endpoint (EDR) → identity (MFA) → data (encryption/DLP) → people (awareness training).
Sample question: "If an attacker gets past your firewall, what stops them next?" — walk through the next layers explicitly; don't just say the firewall should have caught it.

Red team vs blue team vs purple team

Core idea
Red = simulates attackers to find gaps (offensive). Blue = defenders — SOC, detection and response (defensive). Purple = a collaborative exercise where red and blue work together in real time so blue learns to detect the specific technique immediately, instead of reading about it in a report weeks later.
Sample question: "What's the value of purple teaming over a standard red team engagement?" — it closes the feedback loop faster; findings turn into working detections in the same session rather than sitting in a report.

Vulnerability vs exploit vs threat, and CVSS

Core idea
Vulnerability = a weakness. Exploit = code or technique that takes advantage of it. Threat = someone with both intent and capability to actually use it against you. CVSS reflects technical severity, not business risk — a critical CVSS finding on an isolated, non-internet-facing test box is often lower real-world risk than a medium one on a public-facing system.
Sample question: "How do you prioritize vulnerability remediation?" — CVSS as a starting point, then weight by exposure (internet-facing?), asset criticality, and whether there's a known exploit actively used in the wild (CISA's KEV catalog is a good name to drop here).
